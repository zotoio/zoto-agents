MCP Swarm

Agent Skills for the botz MCP Swarm CLI. The botz-mcp-swarm plugin lets your agent capture test suites from live MCP servers, run repeatable assertions and load tests, compare runs, review tool descriptions, record and replay wire traffic, diagnose failures, and upgrade saved suites.

The plugin ships skills and slash commands only — no MCP server or executable is bundled. On first use the skills install the botz host (@zotoio/botz-cli) and its mcp-swarm extension if they are missing.

Install

ClientMarketplace fileInstall
Cursor.cursor-plugin/marketplace.jsonAdd zotoio/zoto-agents as a marketplace, then install botz-mcp-swarm.
Claude Code.claude-plugin/marketplace.json/plugin marketplace add zotoio/zoto-agents, then /plugin install botz-mcp-swarm@zoto-agents
Codex.agents/plugins/marketplace.jsoncodex plugin marketplace add zotoio/zoto-agents, then install from /plugins

The plugin carries a manifest per client — plugin.json (Agent Plugins 1.0, with OpenAI metadata under extensions["com.openai"]), .cursor-plugin/plugin.json, and .claude-plugin/plugin.json — all discovering the same skills/.

Requirements: Node.js 22.13+, npm, and shell access. Live capture and runs need network access to the target MCP server.

First-run setup

Every skill runs commands through the botz host as botz mcp-swarm (never the standalone botz-mcp-swarm or swarm executables). Before the first command in a session a skill:

  1. Runs botz --version. If missing, checks node --version (22.13+) and installs the host with npm install -g @zotoio/botz-cli, telling you it did so. If Node is too old or the global install fails, it stops and reports — it never uses sudo or changes npm configuration.
  2. Runs botz plugins info mcp-swarm --json; if installedVersion is null, runs botz plugins install mcp-swarm.
  3. Confirms with botz mcp-swarm --version and checks a subcommand's --help before unfamiliar options.
npm install -g @zotoio/botz-cli
botz plugins install mcp-swarm
botz mcp-swarm --version

Skills & commands

All skills set disable-model-invocation: true, so they never trigger on their own. Run them by name (for example /mcp-swarm) or through their /z-<skill> command — a light wrapper that loads the skill with the text after the command as the request.

SkillCommandUse it to
mcp-swarm-guided/z-mcp-swarm-guidedBe walked through testing a server: target, credentials, test data, tool selection, and load, then capture, review, run, and summary.
mcp-swarm/z-mcp-swarmCapture, validate, refresh, and run suites directly.
mcp-swarm-compare/z-mcp-swarm-compareCompare two runs or a series, and chart latency, error rate, and tool-eval trends in Cursor's /canvas or a self-contained HTML page.
mcp-swarm-descriptions/z-mcp-swarm-descriptionsReview a server's tool descriptions, examine optimize suggestions, and measure a change with tool evals.
mcp-swarm-record-replay/z-mcp-swarm-record-replayRecord redacted wire traffic and replay it as recorded, at maximum rate, or paced.
mcp-swarm-diagnose/z-mcp-swarm-diagnoseExplain failed runs, missing credentials, and regressions.
mcp-swarm-upgrade/z-mcp-swarm-upgradeUpdate the CLI and migrate saved suites to the current layout.

mcp-swarm-compare ships scripts/runs-dataset.mjs, which needs only Node.js.

Usage

In your agent

/z-mcp-swarm-guided https://api.example.com/mcp
/z-mcp-swarm capture http://127.0.0.1:3000/mcp as docs-server and run it
/z-mcp-swarm run docs-server with concurrency 4 for 30 seconds
/z-mcp-swarm-compare the last two docs-server runs
/z-mcp-swarm-descriptions docs-server
/z-mcp-swarm-record-replay record node server.mjs
/z-mcp-swarm-diagnose why did the docs-server run exit 2?
/z-mcp-swarm-upgrade preview only

CLI commands the skills run

botz mcp-swarm suite capture --url http://127.0.0.1:3000/mcp --name docs-server
botz mcp-swarm suite show --suite docs-server
botz mcp-swarm suite validate --suite docs-server --json
botz mcp-swarm doctor --suite docs-server --json
botz mcp-swarm suite run --suite docs-server --format json

# Inspect server drift without executing target tools
botz mcp-swarm suite refresh --suite docs-server --dry-run

# Compare two run reports
botz mcp-swarm compare --base base.json --head head.json

For stdio servers, substitute --command <bin> and repeated --arg <value> for --url. Capture contacts the live server; review captured arguments and enabled steps before running, because tool calls can change target data. Write-like tools are never silently enabled.

Every suite, report summary, and chart names the server under test as <server name> <version> (<URL or command>), taken from the report's server field (or the saved suite for reports from CLI 0.6.1 and earlier).

Exit codes & CI

Use --format json or --format junit in CI and preserve the process exit status.

ExitMeaning (saved-suite runs)
0Pass
1Failed verdict (offline diagnostics also use 1 for failed checks)
2Configuration / execution error
130 / 143Interrupted

A report existing, or a run where no enabled tools executed, is never treated as success. Manifest runs have different error semantics — inspect the report.

Troubleshooting & limits

  • botz not found / install fails: install Node.js 22.13+ and retry; the skills won't use sudo or alter npm config.
  • Failed or erroring run: start offline with suite validate and doctor (no target or model contact), or run /z-mcp-swarm-diagnose. Use doctor --inference for model configuration issues.
  • Missing credentials: doctor reports missing environment-variable names without reading their values.
  • Schema drift: suite refresh --dry-run diffs the live surface without executing tools; review before applying.
  • Existing suite: capture refuses to overwrite unless --force is supplied.
  • Old directories (.botz/suites, .runs, .swarm-data, .otel): run /z-mcp-swarm-upgrade (needs mcp-swarm 0.6.1+). Skills installed by CLI 0.6.x can be removed with botz mcp-swarm skills uninstall.
